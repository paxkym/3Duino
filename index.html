To perform this task, the pinout of the device must be established. This can be found from numerous sites, but I will use an adaptation from 3DBrew:

  • Pin 1: Ground
  • Pin 2: Clock
  • Pin 3: Ground
  • Pin 4: ROM select/RCS (active low)
  • Pin 5: Reset (active low)
  • Pin 6: Save select/ECS (active low)
  • Pin 7: Ground
  • Pin 8: 3.3 volts
  • Pin 9: D0
  • Pin 10: D1
  • Pin 11: D2
  • Pin 12: D3
  • Pin 13: D4
  • Pin 14: D5
  • Pin 15: D6/CIPO
  • Pin 16: D7/COPI
  • Pin 17: Ground
Note that the pins are numbered from left to right, from the perspective of the back of the card where the gold pins are when the card is upright.

Reading save data

It appears as though save data is much easier to read than the actual ROM. This is because the chip which stores the save information is well-documented and can be bought online (datasheet here) To read save data, pin 6, heretofore referred to as ECS, is pulled low. Then, the 3DS will send a command asking for data, and then the cart will respond with save information. According to 3DBrew, data pins D4 through D7 are the pins used to transmit save data. According to problemkaputt, only D6 and D7 are used. However, upon checking the datasheet, the latter is correct. To test these conflicting ideas, I hooked an Arduino up to a gamecard, set ECS to low, and sent the following commands: 0x03 0x00 0x00 0x00 The commands were sent serially, so each bit was sent through pin D7, since this is the COPI pin. Every other pin was kept at 0. Then, I ran the clock, and, sure enough, save information was sent through pin D6 (because that is the CIPO pin). That wraps up the save data.

Reading ROM data

If one decides to read online about the ROM data transfer protocol, it may be concluded that this is how the 3DS gamecard protocol works: Pull pin 4 (RCS) down, and then the 3DS sends some data to the gamecard, and the gamecard sends data back. This may as well be true, but, as mentioned previously, whatever protocol is listed on the sites currently on the internet does not work. Command structure
It does indeed seem as though commands are sent through D0-D7, and that commands are active when RCS is low. Moreover, the 3DS sends commands to the gamecards, and vice versa. Let us now analyze the actual commands themselves.
Initial commands
When the gamecard is plugged into the 3DS, regardless of which card it is (whether 3DS or DS, whether Ocarina of Time or Animal Crossing, etc), the console sends the following commands to the gamecard: 48 51 F8 51 D9 90 D8 18 18 18 What these commands mean is unknown
