The encryption problem

I will not go into excessive detail about the known parts of the 3DS gamecard protocol, since it can be found everywhere online and I don't want to clutter this article. The gist is that there is a bunch of unencrypted data sent to the 3DS by the gamecard when it is first plugged in, followed by encrypted data. The encrypted data is encrypted using a known set of algorithms, which take into account both data from the unencrypted section of the card, as well as some secret information in the 3DS itself. The hard part of all of this is figuring out what that secret info actually is.

A strong start

How can one possibly hope to figure out such a thing as this? First, we (I will use the first person for the remainer of this article, simply because it is easier, and this is not a professional setting like a paper or something) must find all of the already known info about the protocol. There only appear to be two websites which can aid with this: 3dbrew.org, and Martin Korth's website (no$).
